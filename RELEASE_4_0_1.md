# Release 4.0.1

**Release Date:** 2026-10-23

This patch release fixes a denial of service in language tag parsing (see Security below) and makes `taihei-i18n` more robust against unusual input. Language tags are now validated subtag by subtag instead of with a regular expression, and are limited to 255 characters. Their canonical form no longer depends on the JVM's default locale, and error messages escape control characters before echoing input. Several inputs that used to throw while formatting now produce a value: a long or full `timeStyle` on a zoneless time, an unknown style on Scala.js, a numeric `.match` key out of `Int` range, and a throwable without a message. The MessageFormat 2.0 parser no longer slows down quadratically on templates with many declarations or cases.

The release also tidies the build and release tooling. MiMa now compares a tagged release with the release before it, the release flow in the Makefile is hardened, the sync of the skill docs to an earlier, private marketplace is gone, and leftover references to earlier project names are removed from the docs and comments. The public API is unchanged.

## Security

In 2.0.0 (as `fish.genius::genius-i18n`), 3.0.0 (as `com.edoframework::edo-i18n`) and 4.0.0,
`Language.parse`, `Language.of`, `Language(tag)` and the JSON decoders of `Language` and `Message`
could throw `StackOverflowError` on the JVM for a language tag of a few kilobytes. An application
that reads a language tag or a `Message` from an untrusted source should upgrade. Advisory:
[GHSA-45w8-x6c8-w4hg](https://github.com/taiheiframework/i18n/security/advisories/GHSA-45w8-x6c8-w4hg). If you cannot upgrade, refuse
any tag longer than 255 characters before calling these functions.

## Upgrading

Change the version to 4.0.1. No code changes are needed:

```scala
mvn"dev.taihei::taihei-i18n:4.0.1"       // Mill, JVM
mvn"dev.taihei::taihei-i18n::4.0.1"      // Mill, Scala.js
"dev.taihei" %%% "taihei-i18n" % "4.0.1" // sbt
```

Users of `com.edoframework::edo-i18n:3.0.0` or `fish.genius::genius-i18n:2.0.0` move to
`dev.taihei::taihei-i18n:4.0.1` as described in the README.

## Highlights

- **Stricter, bounded language-tag parsing** - `Language.parse` checks each BCP 47 subtag in a single pass and refuses tags over 255 characters. It accepts exactly the same tags as the previous regular expression up to that length.
- **Locale-independent canonical tags** - Tags are case-converted as ASCII, so `Language("IT")` gives `it` even under a Turkish default locale.
- **No more exceptions from date/time styles** - A `long` or `full` `timeStyle` on a `LocalTime` or `LocalDateTime` falls back to `medium` on the JVM. On Scala.js, unknown styles fall back to `medium` and styles are read in any case.
- **Linear-time template parsing** - Keyword checks in `MessageFormat2` read the template in place. A `.match` with thousands of cases now parses quickly.

## Changelog

### Changed
- `Language.parse`, `Language.apply`, `Language.of` and the JSON decoders refuse a tag longer than 255 characters after trimming. A 100 KB input is rejected cheaply, with a short error message that does not echo the input.
- `Language.parse` validates tags subtag by subtag in the order language, extlang, script, region, variant, extension, private use, instead of using a regular expression. A property test checks that it accepts the same tags as the 4.0.0 check.
- The error for an invalid tag now escapes everything outside printable ASCII as `\uXXXX`. Line breaks and terminal control sequences from caller input therefore do not reach logs verbatim.
- MiMa's baseline (`release.mimaBaseline`) is now the newest `v`-tag reachable from HEAD that is not on HEAD itself. On a tagged release commit, a release is therefore no longer compared with itself, which used to fail in CI until Central had synced.
- The release flow in the Makefile is hardened:
  - Release state is kept in the repository as `.release-state.json` (gitignored) instead of `/tmp`.
  - Tracked or symlinked state and notes files are refused.
  - Files are written to a temporary file and renamed into place.
  - `release-finalize` refuses an already-tagged version and a version that does not follow the current one.
  - `release-abort` validates the version it reads.
  - Release notes are generated by a `claude` call with no tools and no user settings, with `build.mill` and the diff supplied in the prompt.
- The skill docs are renamed from `library-genius-i18n` to `taihei-i18n` and now explain how to copy the skill into your own plugin or project.
- `README.md` gives 4.0.1 in the quick start and names both user ids of the release key, `Taihei Framework Releases <releases@taihei.dev>` and the earlier `Edo Framework Releases <releases@edoframework.com>`, and the keyservers where the key is published.
- `NOTICE` records the original copyright of the MIT-licensed genius-i18n code and the permission to relicense it under Apache 2.0 from 3.0.0.

### Fixed
- Canonicalizing a language tag no longer depends on the default locale. Previously `String.toLowerCase` and `toUpperCase` could turn `IT` into `ıt` under a Turkish locale.
- JVM: a `long` or `full` `timeStyle` on a `LocalDateTime` or `LocalTime` no longer throws `DateTimeException` and now formats with `medium`.
- JVM: style names are lower-cased with `Locale.ROOT`, so `MEDIUM` is recognised under a Turkish default locale.
- Scala.js: an unknown `dateStyle` or `timeStyle` no longer makes `Intl` throw a `RangeError` and falls back to `medium`, as on the JVM. Styles are now case-insensitive, for example `LONG`.
- `MessageFormat2`: a `.match` key such as `=abc`, or a number beyond `Int` range such as `99999999999`, now matches no count instead of throwing.
- `MessageFormat2`: keyword detection (`.input`, `.let`, `when`, `.match`) no longer copies the rest of the template on each check, which made parsing quadratic in the number of declarations and cases.
- `Message.of(throwable)` for a throwable without a message now uses the throwable's `toString`, its class name, instead of storing `null`.

### Removed
- The `sync-skill-docs.yml` workflow and `scripts/sync-skill-docs.sh`, which pushed the skill docs to an earlier, private marketplace. Nothing in the repository publishes the skill anymore.
- References to earlier, private tooling and an internal ticket id (now given as "2.0.0") from docs and code comments.
